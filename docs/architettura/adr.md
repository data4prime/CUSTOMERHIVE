# Registro delle decisioni di architettura (ADR compatto)

> Letto da `/architect` e `ch-architect-analyst`. Serve a **non riproporre**
> ciò che è già stato deciso. Una riga di contesto, la decisione, il perché, e
> cosa NON fare. Le nuove decisioni si aggiungono anche con
> `tokensave_record_decision` (memoria di sessione), ma **questo file è la
> fonte**: è versionato e visibile a tutti.

| # | Decisione | Perché | Non fare |
|---|---|---|---|
| A1 | Mantenere namespace/alias/tabelle `crudbooster`/`cms_*` (via `class_alias`) | Ogni cliente ha controller custom copiati a mano in momenti diversi; la compatibilità deve reggere finché *tutti* sono migrati | Rinominare in blocco le 1400+ occorrenze |
| A2 | Migrazione auth "strangler fig": sessione custom + guard Laravel in parallelo | Zero downtime in produzione | Passare di colpo ai guard o togliere la sessione custom |
| A3 | CSRF disabilitato globalmente | Scelta nota e documentata (`auth-csrf-licenza.md`) | Riattivarlo "di passaggio" in un refactoring |
| A4 | Test su MySQL vero (`customerhive_testing`), non SQLite | Stesso motore della produzione | Spostare i test su SQLite |
| A5 | Ambiente locale sempre Docker | Riproducibilità; `vendor/` e `storage/framework/` su volumi nativi | Cercare php/mysql sull'host |
| A6 | SMTP solo dai Settings, via `MailSettings` | Una sola sorgente di configurazione | Leggere `config('mail')` direttamente in codice nuovo |
| A7 | `hide_form` invece di rimuovere da `$this->form` | Il save azzera i campi assenti | Togliere elementi dall'array `form` |
| A8 | Pint (PSR-12) solo `--test` sui file toccati; Larastan livello 0 con baseline su `app/Helpers` e `Controllers/System` | Evitare diff enormi in codice in produzione | Lanciarli sull'intero repo |
| A9 | Refactoring architetturale su branch dedicato, un batch alla volta, piano approvato prima | Rischio produzione | Implementare l'intero piano in un colpo |
| A10 | UI: Bootstrap 5.3 + Bootstrap Icons in locale, token `var(--ch-*)`, flag `CH_UI_V2` | Rimozione AdminLTE | Reintrodurre AdminLTE |
| A11 | (lo spostamento in `App\Models\` è sostituito da A17) Modelli: restare in `App\` (niente `App\Models\`) per ora; relazioni Eloquent **additive** con nomi nuovi, metodi esistenti come wrapper; local scope sì, **global scope per tenant no** | Il motore usa `DB::table()` in 400+ punti (un global scope non li coprirebbe); i controller dei clienti chiamano i metodi dei modelli; `App\User` è legato a Sanctum (`tokenable_type`) | Spostare/rinominare i modelli senza alias e morph map; sostituire i metodi pubblici esistenti; global scope tenant (piano 317) |
| A12 | Autorizzazioni ChatAI su **tabelle dedicate** (`chatai_groups_allowed`, `chatai_tenants_allowed`), non su `items_allowed`/`tenants_allowed` di Qlik | Le due tabelle Qlik sono in produzione e `item_id` è già lo spazio di id dei `qlik_items`: condividerlo fa collidere conf ChatAI e item Qlik (piano 318) | Aggiungere `chataiconf_id` alle tabelle Qlik; riusare `item_id` per altri tipi di oggetto |
| A13 | Le rotte custom di sistema (`web.php`, `api-documentation`, `mashup*`) stanno sotto `CBBackend`; restano pubbliche solo login/forgot/MFA, `health`, `qi/{proxy_token}`, `uploads/*`. **Sostituisce** la scelta "mashup pubbliche per design" del doc 076. S3 (endpoint SQL generici di `CBController`) lasciato aperto per scelta della persona | Un ospite poteva svuotare `module_tenants` via `save_enable` (doc 324); con CSRF off (A3) un'azione di scrittura senza login è sfruttabile da chiunque | Aggiungere rotte custom fuori da `CBBackend` senza motivarlo; riaprire le mashup in pubblico senza una decisione esplicita; togliere `postDataQuery`/`getUpdateSingle` senza aver cercato l'uso nel JS dei clienti |
| A14 | Form Request: cartella `app/Http/Requests/<Area>/`, primo esempio `StoreApiTokenRequest` (doc 327). Nei metodi che sovrascrivono `CBController` (`postAddSave()` ecc.) il Form Request si costruisce con un metodo statico (`validateCurrent()`), non dalla firma e non con `app(Classe::class)` | Il padre non ha parametri (override con parametro = errore fatale; opzionale = Laravel passa `null`); Larastan (`AppMakeHelper`) risolve davvero le classi passate ad `app()` durante l'analisi, eseguendo `authorize()` senza sessione: warning non ignorabile visibile solo da cache vuota | `app()`/`resolve()`/`make()` con una classe FormRequest nel perimetro Larastan; cambiare la firma di un metodo di `CBController`; far diventare un permesso negato un 403 dove oggi è un redirect con `denied_access` |
| A15 | `/storage/uploads/...` resta pubblico (servito da Apache via symlink `public/storage`, non da Laravel); la rotta `uploads/*` (`FileController@getPreview`) è un residuo morto che ora risponde 404 sui file reali (prima 500) e resta fuori da `CBBackend`. Proteggere davvero i file (opzione B: servirli da Laravel con controllo accessi; opzione C: bloccare solo i campi sensibili) è **rimandato**, da decidere dopo aver capito quali file sono sensibili | Mettere la rotta dietro login non protegge nulla (doc 325); B cambia gli URL salvati in DB e richiede migrazione dati e passaggio per ogni cliente | Proteggere solo la rotta `uploads/*` credendo di proteggere i file; cambiare il formato degli URL salvati senza migrazione per-cliente |
| A16 | `AdminChatAIController::send_message()` (chat fluttuante) usa la conf `primary` per **tutti** gli utenti loggati con licenza ChatAI, senza `can_see_item`: **voluto** (decisione della persona, 2026-10-30). `send_message_agent()` invece controlla `can_see_item($agent_id)` (doc 329) perché l'agente è scelto dall'utente | La chat fluttuante è per chiunque abbia il modulo; l'autorizzazione per gruppo/tenant vale per gli agenti scelti dalla pagina (`content_view`) | Aggiungere `can_see_item` a `send_message()` senza una nuova decisione; togliere il controllo a `send_message_agent()` |

| A17 | I modelli si spostano in `App\Models\` **uno per batch**, con `class_alias` del vecchio nome in `app/Support/legacy_crudbooster_aliases.php` e, se serve, una migration per i dati che contengono il nome della classe. Primo: `User` (doc 336, con migration di `personal_access_tokens.tokenable_type`); poi, per scelta della persona, il cluster `Tenant`/`Group`/`Role`/`UsersGroup` in un solo batch, senza migration (doc 337). **Sostituisce A11 per lo spostamento** (relazioni additive e local scope restano; global scope tenant ancora no) | I controller custom dei clienti usano `App\User` & co. per nome: l'alias li tiene vivi finché ogni cliente non è migrato; l'update dei clienti lancia `php artisan migrate`; Sanctum salva il nome della classe nel DB | Spostare un modello senza alias; togliere l'alias prima che tutti i clienti siano migrati; usare `sed` inline con backslash per rinominare i namespace (vedi lezione del 2026-10-30) |

Per aggiungere una decisione: nuova riga con numero progressivo. Una decisione
superata non si cancella: si marca `(sostituita da A#)`.
