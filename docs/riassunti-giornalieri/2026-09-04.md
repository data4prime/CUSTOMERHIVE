## Export Data

- Il nome file di default usava il letterale "Report" invece del nome del
  modulo — dipendeva da una variabile `$module_name` mai valorizzata per
  quasi nessun controller. Sostituito con `CRUDBooster::getCurrentModule()->name`.
- **Export XLS/CSV sempre in errore 500**: `PhpSpreadsheet` legge la
  tabella generata con `DOMDocument::loadHTML()`, un parser rigoroso — un
  placeholder per le immagini vuote conteneva un `&` non valido come
  entità HTML (`http://placehold.it/50x50&text=...`, doveva essere `?text=`)
  e i valori venivano scritti nell'HTML senza alcun escape: bastava una
  riga con un'immagine vuota, o un valore con `&`/`<`/`>`, per far crashare
  l'intero export. Corretto il placeholder e aggiunto `htmlspecialchars()`
  su tutti i valori scritti per xls/csv (il PDF, che usa dompdf, tollera
  l'HTML e resta invariato).
- **Separatore/delimitatore CSV configurabili**: aggiunte due select nel
  popup Export (virgola/punto e virgola/tabulazione/pipe, doppio/singolo
  apice), applicate via `WithCustomCsvSettings` di Laravel-Excel.

## Ordini Vendita: salvataggio sempre in errore

- `mg_ordini_vendita/add-save` falliva con `Incorrect integer value` sulla
  colonna `stato`: creata come colonna **Numero** nel Module Generator, ma
  il form la mostra come **Select** con etichette testuali
  ("In Lavorazione" ecc.) — tipo colonna e tipo widget sono scelte
  indipendenti nel generator, e chi ha configurato il modulo ha scelto
  "Numero" per errore. Corretto con un `ALTER TABLE ... MODIFY stato
  VARCHAR(255)` diretto sul DB locale (nessuna migration, solo per
  sbloccare i test, su richiesta esplicita).

## Statistic Builder: widget bloccati in "loading"

- Le due dashboard multi-serie (Chart Area/Line/Bar) andavano in 500 con
  `Undefined array key`: il codice esegue una query per serie e ricompone i
  punti con un **indice posizionale**, corretto solo se tutte le serie
  hanno lo stesso numero di righe nello stesso ordine — falso non appena
  una serie ha meno mesi con dati di un'altra. Corretto indicizzando per
  **label** (mese) invece che per posizione, con `?? 0` per le combinazioni
  mancanti — bug identico nei tre widget (copiato tra loro). Aggiunto anche
  un gestore `.fail()` sul caricamento dei widget: prima, se il server
  rispondeva con un errore, lo spinner restava lì all'infinito senza che
  l'utente sapesse perché — ora appare un box rosso con il messaggio
  d'errore.

## Permessi upload (server dev + codice)

- Diagnosticati due `Permission denied` sul server (`app/Http/Controllers`
  per il Module Generator, poi `storage/app/public` e le sue sottocartelle
  mensili) — risolti lato server con `chgrp`/`chmod` (mai collegandosi
  direttamente: solo istruzioni all'utente).
- **Causa radice trovata nel codice**: `Storage::makeDirectory($path, 0777, true)`,
  usato in 5 punti (`CBController`/`SettingsController`/`CRUDBooster.php`),
  passa argomenti che il metodo reale (`FilesystemAdapter::makeDirectory($path)`)
  ignora silenziosamente — senza una `visibility` esplicita sul disco
  `local` di default, Flysystem crea cartelle/file con la visibilità
  privata interna (0700/0600). Corretto aggiungendo `visibility`/
  `permissions` (0775/0664) a `config/filesystems.php` e ripulendo gli
  argomenti morti nelle 5 chiamate.
