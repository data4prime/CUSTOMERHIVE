# 2026-09-16 — Fix cross-tenant nei popup datamodal, modulo Logs in Privileges, export/import moduli, bug allineamento bottoni, tentativo testing Scenario A

## Sicurezza: popup "datamodal" mostravano record di altri tenant

Segnalato dall'utente: in alcuni campi "datamodal" (popup di ricerca/
selezione) un tenant admin vedeva record di altri tenant. Causa:
`CBController::getModalData()` non applica scoping automatico per
tenant, dipende dal `datamodal_where` impostato da ogni form — due punti
lo lasciavano vuoto su endpoint raggiungibili da un tenant admin (non
solo superadmin):

- `AdminGroupsController::members()` — popup "aggiungi membro" a un
  gruppo, tabella `cms_users`.
- `AdminCmsUsersController::groups()` — popup "aggiungi a gruppo" per un
  utente, tabella `groups` (via `group_tenants`).

Corretti valorizzando `datamodal_where` in base a
`UserHelper::isTenantAdmin()`. Altri usi analoghi verificati e scartati
come falso allarme (tutti dietro `isSuperadmin()`). Vedi
[070](../refactoring/070-datamodal-leak-cross-tenant.md). **Aggiornato
in giornata** (modifica di un'altra sessione, non ancora vista nel
dettaglio qui): `CBController::getModalData()` ha ricevuto anche uno
scoping generico automatico per le tabelle `mg_*` del Module Generator.

## Privileges: modulo Logs non assegnabile a nessun ruolo

Causa a valle della segnalazione precedente: il modulo Logs
("Log User Access", `cms_logs`) ha già lo scoping per tenant pronto in
`LogsController::hook_query_index()`, ma non compariva mai nella pagina
Privileges (`getAdd()`/`getEdit()` filtrano i moduli assegnabili con una
whitelist che non lo includeva) — nessun ruolo, incluso Tenant Admin,
poteva riceverne il permesso. Corretto aggiungendo `cms_logs` alla
whitelist. Vedi [071](../refactoring/071-privileges-modulo-logs-non-assegnabile.md).

## Nuova funzionalità: export/import moduli (Module Generator)

Discusso il caso d'uso (portare un modulo custom tra ambienti, oggi
processo manuale — vedi [[project-client-update-process]]) e il design:
JSON portabile (riga `cms_moduls`, schema tabella, i tre blocchi
config/col/form letti dal controller generato) che l'import rigioca
attraverso le stesse funzioni già usate/messe in sicurezza dal wizard
(`CRUDBooster::generateController()`, `var_export()`/`min_var_export()`),
invece di reinventare la scrittura file. Deciso con l'utente: **niente
wiring automatico di menu/privilegi** — resta manuale dopo l'import.

Implementato in `ModulsController.php`: `getExport($id)` (istanzia il
controller generato, legge `col`/`form`/config dalle property pubbliche
invece di ri-parsare il sorgente con `eval()`), `getImport()`/
`postImport()`, tre metodi privati di supporto
(`createImportedTable()`, `replaceControllerBlock()`,
`writeImportedColumns/Form/Config()`), pulsanti "Export" (per riga) e
"Import Module" (in testata). Verificato `getExport()` dal vivo contro
un modulo reale del DB dev (Ordini Vendita), nessun errore — emerso un
bug pre-esistente non introdotto da questo lavoro:
`CRUDBooster::getTableStructure()` restituisce `size: "int"` (stringa)
invece di un numero per colonne intere senza display width esplicito
(tipico di MySQL 8). **Non testato dal vivo un import reale** (creerebbe
tabella/file/riga vere) — da fare quando si riprende.
**Non ancora documentato** in `docs/refactoring/` (proposto un
`072-...md`, mai confermato dall'utente prima di passare ad altro).

## Bug UI: icona/testo disallineati nei bottoni di form

Segnalato su `/admin/users/detail/1` (pulsante "Edit Data"). Causa:
`body.ch-shell .box-footer .btn` in `public/css/theme.css` non aveva
`display: inline-flex; align-items: center` a differenza delle regole
`.btn` analoghe già sistemate nel revamp (`.content-header h1 .btn`,
`.selected-action > .btn`, `.input-group-btn .btn`, `#box_main .btn`).
Corretto aggiungendo le stesse tre righe. Verificato dal vivo (screenshot
prima/dopo) che copre sia il form generico `crudbooster::default.form`
(Add/Edit/Detail di qualunque modulo) sia la vista custom
`users/form.blade.php`. Controllati anche gli altri usi di icona+testo
dentro `.btn` nel CSS (modal-footer, input-group-btn, button_action,
box_main): nessun altro caso trovato, solo `.box-footer .btn` mancava.
