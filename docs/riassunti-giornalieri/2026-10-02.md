## Standard UI su Bootstrap 5.3.8 + Bootstrap Icons, fine di AdminLTE (206-209)

Partendo da un'analisi statica delle incoerenze (Bootstrap 5 sopra AdminLTE 2/
Bootstrap 3, tre famiglie di icone, 124 colori hex distinti e 364 stili inline
nelle viste, CDN diversi per pagina) è stato fatto, in un unico lavoro non
ancora committato, l'intervento descritto nei singoli documenti:

- **206 — librerie in locale**: Bootstrap 5.3.8, Bootstrap Icons, jQuery UI,
  interact.js, Raphael/Morris, gridstack, ApexCharts e DataTables 1.13 (BS5) in
  `public/vendor/`, versione fissata, nessun CDN; partial `ch_head`/`ch_scripts`/
  `ch_icons` per tutte le pagine. Vedi
  [`206`](../refactoring/206-ui-standard-librerie-locali-bootstrap-5-3-8.md).
- **207 — icone**: mappa unica FA4/Lucide → Bootstrap Icons (`IconMap`), CSS di
  compatibilità per i `fa fa-*` dei clienti, 647 sostituzioni, picker di menu/
  moduli e widget Small Box. Vedi
  [`207`](../refactoring/207-ui-standard-icone-bootstrap-icons.md).
- **208 — rimozione di AdminLTE**: `ch-layout.css` + `ch-shell.js` al posto di
  CSS/JS di AdminLTE (stesso markup), eliminata la cartella `adminlte/`. Vedi
  [`208`](../refactoring/208-rimozione-adminlte.md).
- **209 — token, componenti, compatibilità**: token `--ch-*` mappati su
  `--bs-*`, `ch-components.css` (campo, select2, pulsanti, badge uguali ovunque),
  classi BS3→BS5, colori e font ricondotti ai token, `ch-compat.css` temporaneo.
  Vedi [`209`](../refactoring/209-ui-standard-token-componenti-compatibilita.md).

Verifiche: viste compilate, 30+ pagine admin reali in locale (200, log pulito),
asset tutti raggiungibili, pagine eseguite in jsdom senza errori JS. **Non**
verificato a vista nel browser; suite di test non lanciata.

Altro:
- Eliminati 14 file morti (`*copy*`, `*_old*`, `*_.blade.php`) e `public/css/app.css`.
- Bug trovato durante la verifica e corretto: i layout dei widget sostituiscono
  `[name]` anche dentro gli `<script>` (rotto lo script del Small Box appena
  riscritto).
- Incidente di processo: uno script di controllo ha richiesto con GET anche link
  `/delete/...`; verificato che non è stato cancellato nulla (nessun log, nessun
  `deleted_at`). Poi corretto per controllare solo file statici.

## Analisi dei `type_components` e consolidamento dei `*_datamodal` (214-216)

Analisi di inventario/duplicazione dei tipi di campo. Tre interventi:

- **214** — SQL injection in `select_to` dei popup `*_datamodal`: il valore era
  concatenato in `whereRaw` nei sette `browser.blade.php`; ora `(int)`.
- **215** — i sette `*_datamodal` delle relazioni (utenti-gruppi, gruppi-membri,
  gruppi-item, gruppi-tenant, item-gruppi, item-tenant, tenant-gruppi) condividono
  campo+modale e tabella del popup in `default/datamodal_relation/`; ogni tipo
  tiene solo la propria query; `getModalData` usa una whitelist al posto dello
  `switch`. ~1000 righe in meno.
- **216** — `select2/info.json` documenta `datatable_orig`; rimosso il residuo
  `info_.json`.

Verifica: render nel container dei 7 componenti e 7 popup su dati reali; suite
completa lanciata su richiesta (218 test, 699 assertion, tutti verdi). Non
verificati nel browser la selezione nel popup e la scrittura nei campi
`description`/`email`/`subtitle`.
